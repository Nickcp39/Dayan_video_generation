# 投资／理念视频市场采集 pipeline v1

建立日期：2026-09-28。负责人：本对话中的研究代理。用户可协助登录，但不需要提供密码或验证码给代理。

## 目标与交付

先研究市场，再决定节目。比较头部投资／知识博主与较小账号的连续作品，回答哪些问题有人看、哪些表达值得借鉴，以及真人短口播可能提供什么原创增量。不要预设“年轻巴菲特”是空白市场，也不要用制作工具已就绪证明有受众。

交付包括：候选账号清单、连续作品台账、组内高／中／低表现对照、内容拆解、观众评论需求线索、证据与缺口记录、可借鉴方法与原创增量表。当前阶段不写节目脚本、不试拍、不生成、不发布。

## 文件与入口

- `scripts/market_research_pipeline.py`：创建批次、登记已有本地证据、输出待办、计算复核绑定值。
- `scripts/check_market_research.py`：独立 checker，生成带时间戳的 JSON 与 Markdown 检查报告。
- `scripts/test_market_research.py`：合成数据回归测试，绝不能将其中的数字或通过结果称为真实调研。
- `research/market/2026-09-28/<platform>/plan.json`：本批规则与固定时间截点。
- 同目录 `data.json`：唯一结构化采集台账；`evidence/` 保存原始观察；`reports/` 保存检查结果。
- `research/market/2026-09-28/STATUS.md`：跨平台接手状态，不另建重复台账。

脚本仅使用 Python 标准库，不发网络请求、不读取浏览器凭据、不自动下载媒体、不运行视频生成。公开页面采集由研究代理通过可用浏览器／搜索工具完成，再登记证据。没有无人值守爬虫或绕过登录的功能。

## G0：预先固定研究规则

首批以中文为主。B 站、抖音、小红书必须分开批次。B 站主指标为播放；后两者主指标为点赞。它们不合并排名；小红书图文保留为外围参考，不计入视频核心样本。

默认每平台六个关键词：投资、理财、价值投资、巴菲特、芒格、决策思维。各看综合／相关与平台可提供的热门排序，按可见顺序记录前10个结果，共最多120个结果位置。热门排序若实际为最多点赞或最多播放，保存页面原标签；不存在该排序则记录受阻，不假装已完成。重复账号合并，广告、影视“投资成本”等误命中也保留排除理由。搜索排序不是全市场排行榜。

选择3个头部候选、2个较小对照账号。这里的“头部”是本次相关领域候选中的相对分类，需要粉丝／作品表现及选入理由，不能仅凭名字、认证或单个爆款。中小账号用于检验相近形式是否依赖大号基础。候选适配度不足时记录事实，不为了凑数称其为同类。

每个选中账号取固定截点前14—365天内、按发布时间倒序的最近连续20条作品；排除置顶导致的排序干扰，保存翻页／列表证据和排除明细。不能只取该账号最火的20条。少于20条则记录耗尽原因，checker 保留 BLOCKED；可在研究结论中说明样本不足，不能补入挑选的爆款冒充连续作品。

20条中再分核心与参考：核心为15—90秒、中文、原创出镜／原创讲解，主题是投资理念、个人理财或决策心理。30—60秒是重点观察区间；15—90秒是预设邻近范围。名人切片、新闻复盘、长视频、图文作为参考而非核心。不能仅凭标题判断原创或时长。

默认每账号核心至少6条才计算其组内高／中／低三条深读；至少3个账号满足此条件，并且同时包含头部与中小账号，才满足核心覆盖。若实际供给不满足，结果应是“拟议形式证据不足”，而非自动扩大时长、换指标或降低配额。

这些配额是本轮工作量与可比性的研究设计，不是平台规律或成功阈值。尚未采样前可基于发现修订，必须增加 revision 并说明原因；开始采样后改变口径应新建批次、保留旧批次。不得为了使检查通过而静默改规则。

## G1：发现与选账号

保存每次搜索的 URL、关键词、页面真实排序、观察时间、前10个结果位置及纳入／排除理由。每个候选登记姓名、主页、平台、当时可见粉丝、出镜／切片形式线索、选择理由。粉丝数是采集时快照，不是作品发布时的粉丝数。

登录受阻时先登记 URL、实际提示和可见范围。用户可在浏览器中自行扫码登录；代理不读写密码、OTP、cookie或身份材料。不得将未登录造成的空列表记成没有作品。验证码与站点限制不绕过。

账号选择需有真实的研究复核记录，不能由脚本自动接受。

## G2：采集连续作品与计数

每条记录：作品链接／ID、账号ID、原始标题、含时区的发布时间、观察时间、实际时长、语言、内容形式、主题及分类理由、播放／点赞／评论／收藏／分享、证据ID。

每个指标结构固定为 `value/raw/precision/reason`。例如页面显示15.6万，存156000、`15.6万`、`rounded`；不可公开的播放存 null/null/unknown/原因。只有真的看到0才存0。评论数、弹幕数不得互换；抖音个人主页“获赞总数”不得代替粉丝数。

同账号用于比较的计数尽量同一时段采集，默认距固定截点不超过48小时、组内观察跨度不超过48小时。超过时不覆盖旧证据，可新开批次重新观察。历史累计播放不能解释为最近播放或增长速度。

列表证据用于核查连续性；作品详情页证据用于核查指标。搜索摘要仅作线索，不能替代核心作品详情。截图／可见页面文字需保存本地原件，登记来源与实际观察时间，自动计算SHA256。只保存必要公开文本；不要批量存储评论用户身份和完整长文／字幕。

## G3：确定对照并深读

checker 按同账号核心作品的主指标计算中位数，固定选择最低、最接近中位数、最高各一条。相同计数按作品ID稳定排序；若不足3种不同计数，不强行宣称冷热分化。数值相等或四舍五入相近时仅作描述。不同发布时间、主题、流量来源仍是混杂因素，不能称控制实验。

对每条选中作品完整观看后记录：观众需求假设、开头如何进入问题、内容结构、说话方式、镜头／字幕／图解、可信度来源、可借鉴的通用方法、我们可能增加的事实或判断、不应照搬的独特表达、局限。

观察不到声音或完整视频时，不写 full_watch；保留“只看标题／部分画面／文字”的记录和缺口。代理研究复核与用户认可不同，reviewer_role 必须如实记录，不能冒充用户。

评论默认记录可见排序的前10条，匿名概括需求、质疑、认同或追问；不是挑10条支持观点的评论。保存排序与评论区域证据。不足10条说明原因；评论不可见可以记录 login_required/disabled/unavailable/none。无评论证据时不得推断主流观众、年龄或购买意愿。

## G4：综合与结论上限

将结论逐条分为 observation（观察）、hypothesis（假设）、unknown（未知），关联作品和证据，并写局限。事实观察可以是“本组高播放作品同时出现某特征”，不能直接升级为“这个特征导致高播放”。

公开计数不能验证完播率、单条涨粉、回访、受众画像或因果。checker 会阻止将这些及全市场排名列为已证实观察。它无法理解所有措辞，也无法证明截图真实、作者诚实、是否完整观看或样本代表性；最终综合复核必须逐项审读，不能只按 PASS 下结论。

借鉴表重点为：观众问题 → 对方表达方法 → 高低样本是否一致 → 我们可增加的经历／解释／判断 → 尚缺证据。仅换脸、换词、加字幕不自动构成实质原创增量。不生成规避查重或伪装原创的方案。

## Checker 与恢复

| 阶段 | PASS 的含义 | BLOCKED 的典型原因 |
|---|---|---|
| plan | 规则结构可读、当前已登记证据无结构性错误 | 已填数据缺证据；尚未要求市场覆盖 |
| collection | 发现、选择、连续样本、核心覆盖及复核满足本批口径 | 登录、样本不足、缺详情证据、快照过期 |
| analysis | 所需高／中／低深读、评论状态、结论台账与复核齐备 | 未完整观看、来源不足、结论越界、复核过期 |

FAIL 表示数据／引用／路径／哈希错误；修复后重跑。BLOCKED 表示证据或覆盖未满足，可继续补缺，但不能跳到“已完成市场验证”。退出码0=PASS、1=FAIL、2=BLOCKED。每次检查新增报告，不覆盖历史报告。

复核绑定 plan 和当前记录。新增证据或改数据会使相关复核过期，这是保守设计：先完成采集再复核。binding 命令仅输出哈希，绝不自动填 accepted。对话中断后，先读STATUS和最新报告，再继续缺项；不重置整个台账，不盲目重复采集。

同时只能有一个写入者修改同一data.json。登录限制连续尝试一次仍无效就记录限制，并在其他可见页面继续工作。不得为了“数据量”无限搜索；默认上限达到后按已有材料写明结论与缺口。

## Windows 命令

当前机器 Python 不在 PATH，可使用已存在的解释器：

```powershell
$researchPython = 'C:\Users\nickc\anaconda3\python.exe'
& $researchPython scripts/market_research_pipeline.py init --run research/market/2026-09-28/bilibili --as-of '2026-09-28T07:26:20+00:00' --platform bilibili
& $researchPython scripts/market_research_pipeline.py queue --run research/market/2026-09-28/bilibili --stage collection
& $researchPython scripts/check_market_research.py --run research/market/2026-09-28/bilibili --stage analysis
& $researchPython scripts/test_market_research.py
```

init 仅第一次执行，已有非空目录会拒绝覆盖。新批次使用实际截点，不照抄旧时间。登记已有截图／页面文字：

```powershell
& $researchPython scripts/market_research_pipeline.py evidence --run <批次目录> --capture <本地文件> --url <来源URL> --observed-at <实际时间含时区> --method browser_text --label <内容说明>
& $researchPython scripts/market_research_pipeline.py binding --run <批次目录> --kind content --target <作品ID>
```

记录字段示例见 [MARKET_RESEARCH_RECORDS.md](MARKET_RESEARCH_RECORDS.md)。2026-09-27的零散初查文档仅作候选线索，缺少本流程原始快照的条目不得冒充新的已核验样本。
