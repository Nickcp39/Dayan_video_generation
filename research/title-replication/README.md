# 财经大V 标题与中心思想复刻 pipeline

目标：让 AI 学会 9 个百万级财经频道的**写法**，也就是拿到一个选题后如何立论、如何起标题，并用它们没见过的新视频检验学得像不像。
思路和读论文一样：拆解作者怎么立论、怎么起题，不抄他写过的题目。**选题是给定的输入，不在考核范围内**；考核的是标题和中心思想。

上一版（`../finance-titles/`）存在这些问题，这一版逐条修正：

| 上一版的问题 | 这一版的做法 |
|---|---|
| 只有标题，没有日期、播放量、内容 | 抓取播放量、时长、发布日期和字幕（只抓文字，不下载视频） |
| 両学長 54%、中田 58% 的标题是 YouTube 自动翻译的英文，并被截断 | 按频道母语请求页面，日本标题 100% 为日文原文 |
| 両学長 383 条重播被计为独立视频 | 剔除重播；调试集、测试集中与训练集同题的视频也剔除 |
| "语义拆解"实际是正则计数 | 用 LLM 逐条拆解标题手法和视频论点，统计由程序计算 |
| 测试话题是看着真实标题写的，存在泄漏；自己生成、自己打分 | 素材由另一次调用只读字幕生成，不让它看到标题，另做泄漏检查；盲评；设两个基线方案 |
| 订阅数多处有误（如财经冷眼报约 150 万，实际 61.4 万） | 以 yt-dlp 读取的频道数据为准 |

## 流程

```
s1 列表 → s2 切分 → s3 字幕 → s4 拆解 → s5 写作指南 → s6 中性素材 → s7 仿写 → s8 评测 → s9 报告
                                          ↑                                        │
                                          └──── 用调试集结果修订指南（不看测试集）────┘
```

| 步骤 | 做什么 | 输出 |
|---|---|---|
| s1 `s1_list.py` | 抓取每个频道 /videos 页的全部长视频：母语标题、播放量、时长 | `data/listing/` |
| s2 `s2_split.py` | **按时间切分**：最新 15% 为测试集，再往前 10% 为调试集，其余为训练集。剔除重播和同题视频。候选顺序用固定随机种子打乱 | `data/split/`、`out/split_counts.json` |
| s3 `s3_subs.py` | 按候选顺序抓字幕，取每组前 N 条有字幕的视频（训练 30 / 调试 10 / 测试 20）。优先人工字幕，其次原语种自动字幕 | `data/subs/`、`data/meta/` |
| s4 `s4_decompose.py` | **语义拆解**。① 标题：每个频道抽样 300 条训练标题（播放量前 100 加随机 200），拆出句式模板、钩子、留白、人称、情绪、数字作用、固定标签；② 内容：每期视频拆出选题、中心思想、论点类型、切入角度、论证骨架，以及标题与论点的关系 | `data/decomp/` |
| s5 `s5_guideline.py` | **写作指南**。把训练集的统计和拆解归纳成一份 7 节指南：定位、选题到论点、标题公式、标题与论点的关系、硬指标、禁忌、写作步骤，另附 8 个示范。`revise` 子命令用调试集结果修订 | `out/guidelines/<频道>.v<n>.md` |
| s6 `s6_briefs.py` | **中性素材**。只给字幕、不给标题，去掉作者的观点和修辞，只留事实；再检查素材里有没有出现真实标题的原话（中文连续 6 字或英文连续 4 词），有就重写一次 | `data/briefs/`、`out/briefs_leak.json` |
| s7 `s7_generate.py` | **仿写**。三个方案拿到同样的素材，各写 3 个候选再选 1 个：零样本（只给频道名）、少样本（30 条旧标题）、写作指南 | `data/gen/` |
| s8 `s8_evaluate.py` | **评测**：盲测辨真（骗过率）、频道归属、中心思想一致度（0–3）、抄袭检查、风格指标 | `out/results/` |
| s9 `s9_report.py` | 生成报告，以及一个给人做的盲测网页 | `out/REPORT_<set>.md`、`out/blind_test_<set>.html` |

判断写作指南是否有效：它必须在测试集上同时胜过两个基线方案，同时没有抄袭标记。
测试集只在指南定稿后跑一次。

## 运行

依赖：Python 3.9+；`tools/yt-dlp.exe`（官方 release，不入库）；本机已登录的 Claude Code CLI，作为 LLM 后端。

```powershell
cd research/title-replication/pipeline
python s1_list.py
python s2_split.py
python s3_subs.py                       # 可断点续传；YouTube 限流时自动保存进度后退出
python s4_decompose.py titles
python s4_decompose.py content
python s5_guideline.py build            # 写作指南 v1，只用训练集
python s6_briefs.py
python s7_generate.py --set dev
python s8_evaluate.py --set dev
python s5_guideline.py revise           # 用调试集诊断，生成 v2
python s7_generate.py --set dev --systems guide
python s8_evaluate.py --set dev
python s7_generate.py --set test        # 指南定稿后，测试集只跑一次
python s8_evaluate.py --set test
python s9_report.py --set test
```

模型按角色配置，见 `pipeline/common.py` 的 `MODELS`：拆解和素材用 sonnet，写指南、仿写、评审用 opus。可以用环境变量 `TR_MODEL_<ROLE>` 覆盖，并发数用 `TR_WORKERS` 控制。所有 LLM 调用都缓存在 `data/llm_cache/`，重跑不会重复计费。

## 结果（测试集，2026-10-01）

测试集为 9 个频道各 20 期最新视频，共 180 期，模型在训练阶段没有见过这些视频。生成用 Opus 5.5，评审也用 Opus 5.5。完整报告见 [out/REPORT_test.md](out/REPORT_test.md)。

| 方案 | 骗过率（50% = 真假难辨） | 中心思想 /3 | 中心思想 ≥2 分 | 频道归属 | 照搬旧标题 |
|---|---|---|---|---|---|
| 零样本（只给频道名） | 12% | 2.16 | 85% | 78% | 0 |
| 少样本（30 条旧标题） | 17% | 2.28 | 89% | 77% | 0 |
| 写作指南 v1（只用训练集） | 14% | 2.29 | 88% | 80% | 0 |
| **写作指南 v2（v1 + 调试集修订）** | **22%** | **2.31** | 88% | 79% | 0 |

真实标题的频道归属准确率是 74%。

结论：

1. **中心思想基本能复刻。** 各方案都有 85% 以上的期数得到 ≥2 分，也就是论点方向一致。写作指南只带来小幅提升，因为中性素材本身已经在很大程度上决定了论点。
2. **标题只复刻了一部分。** 写作指南 v2 是唯一明显胜过零样本的方案（22% 对 12%，n=180，p≈0.01），但离 50% 还很远。分地区看，Graham Stephan 的骗过率达到 70%，小Lin说 35%，日本三家只有 0–10%。v1 在测试集上没有胜过少样本，说明用调试集做的修订是有效的。
3. **仿写最大的破绽是"太像模板"。** 仿写标题被归到正确频道的比例（79%）高于真实标题（74%）。真实作者会频繁用一次性的口语和细节，比如「最最」「到底是个什么情况」「大震災でも一部損？」；AI 则反复套用招牌句式，比如「一口气了解」「初めて明かされる㊙︎」「*JUST*」。评审多数时候就是靠这一点识破的。
4. **另外两类破绽。** 一是系列上下文：真实标题常常接着频道正在做的系列，比如（下）、【総裁選対談】、【切り抜き超まとめ】，只看单期素材无法知道。二是事实细节写错。

下一轮可以改进的方向：给生成器提供该视频发布前最近 10 条标题，作为频道当前的系列上下文；限制招牌句式的使用频率不超过它在训练集里的占比；要求标题至少用一处来自素材的具体细节或口语表达。

## 写新一期

用定稿的写作指南 v2 给新选题出标题和中心思想。提示词和模型与测试时完全相同。

```powershell
cd research/title-replication/pipeline
python write.py ../drafts/china_us_bonds.json                 # 小Lin说
python write.py ../drafts/china_us_bonds.json --channels all  # 9 个频道对比
```

素材格式为 `{"topic": "...", "facts": ["..."]}`，只写事实，不带观点。示例见 [drafts/china_us_bonds.json](drafts/china_us_bonds.json)。
在 Claude Code 里可以直接调用 skill `finance-title-guide`（`.claude/skills/finance-title-guide/`）：给它一个选题或一篇博客，它会整理素材、运行 `write.py` 并核对事实。

## 数据与版权

字幕、视频简介、中性素材都属于原作者内容的衍生物，只保存在本机的 `data/` 下（已加入 git 忽略），不进入公开仓库。
仓库只包含代码、提示词、切分统计、写作指南（引用少量真实标题作例子）和评测结果。

## 频道

见 `channels.json`。财经冷眼只保留统计，不纳入复刻：它的中心思想多是针对真实人物、无法核实的政治指控，批量仿写等于批量制造谣言。
中田敦彦是知识综合频道，高橋ダン订阅数不到百万，两者都作对照保留。

## 已知局限

- 评审模型和生成模型同属 Claude，可能互相"看得顺眼"。所以另外提供 `blind_test_*.html`，供真人盲测。
- 零样本方案并不是真正的"零"：模型可能在预训练时见过这些频道。
- 自动字幕有识别错误；小Lin说的老视频字幕是压在画面里的，YouTube 上没有字幕轨，因此她的样本只能来自有字幕的视频。
